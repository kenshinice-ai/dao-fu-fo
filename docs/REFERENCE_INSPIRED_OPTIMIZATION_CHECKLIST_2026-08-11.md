# 参考站与 previous project 可迁移优化清单

日期：2026-08-11

参考站：[The Bible Atlas](https://bible-atlas-6h7.pages.dev/)
范围：当前 `digital-museum` 与同目录 `previous project` 的地图、时间轴、实体浏览、关系图、URL 状态和详情抽屉实现。

## 结论

当前项目已经具备 map-first 工作区、地图—时间轴—对象面板联动、URL focus/scope/detail、证据与出处分层、详情抽屉焦点管理、双语和 reduced-motion 基础。因此不重复建设这些能力，也不直接复制参考站的深色皮肤。

优先迁移的是参考站背后的交互架构：一个可分享、可恢复的探索状态；同一份派生数据驱动地图、列表、时间轴和关系图；在数据变密时通过聚合、分层和按需展开保持可读性；在每一步都保留证据和来源语境。

## P0：应优先落地

- [x] **P0-1 完整化 URL 状态**
  - 将当前局部 `query`、地图内容图层和可视化密度/缩放层级纳入统一 route state；现有的 `view`、`atlasTab`、`timelineMode`、时间范围、`focus`、`scope`、`detail`、`compare` 继续保留。
  - 借鉴 `previous project/apps/web/src/state.ts` 的 `q`、`layers`、`zoom` 序列化方式，落点为 `packages/museum-core/src/route-state.ts` 及 `AtlasWorkspace`。
  - 验收：复制链接后刷新、浏览器前进/后退、切换中英文，都能恢复同一筛选、地图图层、密度层级和详情状态；不会出现“地址栏看起来一样但页面不同”。

- [x] **P0-2 去掉列表的隐性 80 条上限**
  - 当前对象面板和关系列表用 `slice(0, 80)` 截断，未来数据增长后会出现“计数与可发现内容不一致”。改为虚拟列表或分页/分批加载，保留当前的搜索、空状态和结果计数。
  - 借鉴 `previous project` 的“无硬上限”方向，可采用 `@tanstack/react-virtual`；键盘用户仍须按稳定顺序访问全部结果。
  - 验收：完整数据可被搜索和键盘访问；大数据集不会一次性渲染成巨大 DOM；列表标题明确显示“当前结果 / 总数”。

- [x] **P0-3 建立地图—时间轴—关系图共用的 LOD 层级**
  - 将现有 `depth` 或新增 `zoomLevel` 统一为“时代 / 区域或群组 / 重要对象 / 全部对象”四级。高层显示聚合节点、密度和群组，深入后才展开人物、事件和关系。
  - 同一个层级、焦点和筛选结果要同时影响 `CivilisationMap`、`AtlasTimelineRail`、`RelationNetwork` 与对象面板，不能各自维护一套可见性规则。
  - 验收：缩放或切换层级不会丢失焦点；地图点、时间轴事件、关系节点数量随层级一致变化；每级都保留可进入的文本列表。

- [x] **P0-4 增加地图内容图层、图例和不确定性开关**
  - 迁移 previous project 的 `places / routes / landmarks` 图层模型，并结合本项目的数据语义扩展为地点、路线、人物轨迹、遗址/文化区域等；不要把“传统记忆位置”和“有坐标的历史地点”画成同一种标记。
  - 增加可折叠图例，说明传统颜色、地点/路线/轨迹符号、虚线/半透明/光晕分别代表什么，以及证据强度如何表达。
  - 验收：地图不依赖颜色单独传达信息；用户可以隐藏高密度图层；每个不确定位置或路线都能在图例或详情中找到解释。

- [x] **P0-5 将时间轴升级为“密度 + 范围选择”的主控件**
  - 在现有历史/传统模式、起止年份输入和事件按钮上，增加时代带、事件密度桶、未定年区域和“显示全部”；密集区先聚合，点击后展开。
  - 借鉴 `previous project/apps/web/src/components/TimelineRibbon.tsx` 的 brush/range 思路，但保留当前项目更适合研究阅读的年份输入和文本事件列表。
  - 验收：高密度时期不重叠成噪声；拖动或输入范围会同步过滤地图、对象面板和关系语境；未定年对象不会被静默丢弃；公元前/公元后的边界不出现 year 0。

- [x] **P0-6 关系图改为“可缩放图 + 永久文本兜底”**
  - 当前 `RelationNetwork` 适合局部一跳关系，但固定邻居数量和 SVG 径向布局不适合扩展。迁移 previous project 的 graph tier、缩放、聚合和选中居中思路；节点规模增大时使用 Canvas 或分组显示。
  - 关系图旁始终保留可搜索的邻接列表，显示关系类型、时间、证据/置信度；不要只用颜色区分关系。
  - 验收：100+ 节点仍可交互；移动端可以自动切换到局部图或列表；键盘和读屏用户能通过文本列表完成与图相同的探索。

## P1：完成核心体验后落地

- [x] **P1-1 统一全局搜索与局部搜索**
  - 借鉴 previous project 的 `GlobalSearch`，提供带 `combobox/listbox` 语义的全局搜索，结果混合人物、事件、地点、路线、文本，并显示类型、摘要和计数；对象面板继续保留“当前范围内搜索”。
  - 搜索结果回写统一 focus/detail URL，支持方向键、Enter、Escape、点击外部关闭和中英文内容。
  - 验收：输入一个人物、地点或文本关键词都能直接进入同一个详情抽屉；全局搜索与面板搜索不会产生两套不同的选中逻辑。

- [x] **P1-2 详情抽屉加入相邻浏览和“为何重要”摘要**
  - 当前抽屉的证据、出处、关联语境已经较强；补充在当前筛选结果中的上一个/下一个对象，以及人物—事件—地点—文本的分组关联。
  - 在长证据内容之前增加一段简洁的“在本馆叙事中的意义 / 语境意义”，对应参考站的 significance 区块；完整档案仍作为深入入口。
  - 验收：用户不必关闭抽屉就能连续浏览同类对象；关联项点击后仍复用同一抽屉、焦点管理和 URL 状态。

- [x] **P1-3 统一证据、现实性和置信度的显示文案**
  - 当前部分界面仍可能直接显示 `HISTORICAL_DOCUMENTED`、`historical_inferred` 等内部枚举。建立集中式双语 formatter，把内部值转换为面向公众的“有文献依据 / 推定 / 传统记忆 / 坐标待核”等文案。
  - 地图、列表、关系图、抽屉和来源说明必须使用同一套标签与排序。
  - 验收：用户看不到原始枚举值；同一对象在不同视图中的证据标签一致；标签旁有解释或可进入来源说明。

- [x] **P1-4 借鉴参考站的工作区节奏，但保持本馆轻量编辑视觉**
  - 迁移参考站的 8/16/24 间距节奏、18px 大面板圆角、44px 触控高度、明确的活动态、数量徽标、1px 边界和内部滚动容器。
  - 继续使用当前项目的纸张/矿物色、碑刻与书籍字体、低阴影策略；不引入深色 dashboard、金色宗教旅游风或玻璃拟态。
  - 验收：新增控件与现有 design system 一致；地图工作区仍有博物馆/研究工具气质，而不是参考站的换皮复制。

- [x] **P1-5 把“当前视图的数据说明”放回探索现场**
  - 在时间轴或对象面板下方增加折叠式来源与数据说明，解释年代、坐标、路线、传统叙事和推定关系的范围；Research 页面继续承担完整方法论。
  - 借鉴参考站的 uncertainty note、sources grid 和 rights note，但改写为本项目的证据分层与内容治理语言。
  - 验收：用户在地图/时间轴中遇到不确定对象时，不必离开当前工作区才能理解其依据。

## P2：可选增强

- [x] **P2-1 时间轴播放与人物旅程播放**：把时间轴作为叙事播放器，驱动地图、列表和关系图同步变化；播放时减少 URL 写入，尊重 `prefers-reduced-motion`，默认不自动移动地图。
- [x] **P2-2 地图轨迹叙事**：为人物迁徙或路线增加方向箭头、停留节点和按事件步进；当前已有静态 trajectory，先做手动步进，再考虑动画。
- [x] **P2-3 移动端单视图模式**：在 390px、768px 断点验证“地图 / 时间轴 / 对象 / 关系”一次聚焦一个视觉主体；轨道和标签只在内部容器横向滚动，页面本身不横向溢出；详情使用全屏 sheet。
- [x] **P2-4 大规模数据的分层加载**：参照 previous project 的 index + on-demand 方向，把摘要索引、时间范围事件、地图 bbox 数据和实体详情拆开加载；当前数据量未达到必须拆分的阈值，可在 P0 LOD 完成后再评估。

## 2026-08-11 实施结果

P0/P1/P2 已全部落地：路由 URL 现在恢复搜索、图层、LOD、时间范围、焦点和详情；列表采用渐进式分批显示并保留“显示全部”；地图、时间轴、关系图共享四级 LOD；地图提供地点/路线/人物轨迹图层、不确定坐标样式和图例；时间轴提供密度桶、时代带、范围控件、未定年提示和播放；关系图同时提供局部图与完整文本邻接列表；全局搜索、详情相邻浏览、意义摘要、证据 formatter、数据说明、人物轨迹步进和移动端单视图均已接入。

验证结果：`npm run check`、`npm run test:e2e`、`git diff --check` 通过；Playwright + axe 为 55 passed / 1 skipped，唯一跳过项是需要 Public RC visibility 的环境专用用例；生产构建保留 Vite 的既有大 bundle 非阻断提示。

## 暂不建议直接移植

- [ ] 参考站的深色海军蓝 + 金色主题：与当前已确定的纸张/矿物色博物馆视觉冲突。
- [ ] 参考站的圣经专属字段、作品选择器和经文语义：应抽象成当前项目的文明、传统、证据和展览语境，不能原样套数据模型。
- [ ] 为了“看起来像 atlas”而新增大量动画、发光、地图装饰或自动播放：先保证状态可恢复、证据可解释和移动端可用。

## 建议实施顺序

1. P0-1 统一 URL 状态。
2. P0-2 列表去硬上限，并补齐虚拟化/分批加载。
3. P0-3 建立共用 LOD，再同步改地图、时间轴、关系图。
4. P0-4、P0-5、P0-6 完成地图图层、时间轴密度和关系图兜底。
5. P1-1 至 P1-5 收口搜索、抽屉、证据文案和研究说明。
6. 用 390 / 768 / 1024 / 1440 四个宽度做视觉、键盘、读屏和性能回归，再决定 P2。
