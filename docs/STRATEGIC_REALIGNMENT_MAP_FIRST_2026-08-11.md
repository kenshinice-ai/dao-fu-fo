## 1. 产品重新定义

> 道·儒·佛文明数字博物馆是一张以人物为入口、以时间和空间为骨架、以事件、地点、路线、经典、言论、制度、历史地位与后世影响为关系网络的全历史文明地图。

数字博物馆仍然存在，但层级调整为：

- **Atlas 首页**：第一入口；用户立即在时间和空间中发现人物与交汇。
- **Museum**：把地图中的关键人物、地点和事件组织成策展故事。
- **Entity dossier**：解释人物、经典、地点、事件和关系。
- **Research**：展示来源、版本、权利、置信度和审核状态。

地图不是一个独立功能，而是所有内容的共同舞台。人物卡片、展厅、原典和研究档案都从地图进入，也都能返回原来的地图场景。

## 2. 不再使用 MVP 边界

原“隋唐 MVP”保留为历史规划和一个重要策展专题，不再代表产品总范围。

新的范围规则：

- 时间上从神话/传统起源、先秦诸子、佛教印度源流一直延伸到近现代传播；
- 空间上覆盖中国、印度、尼泊尔、中亚、东南亚、日本、朝鲜半岛及重要传播节点；
- 数据数量不设最终上限，依靠时代、区域、人物重要度、聚合与地图缩放控制屏幕密度；
- 新内容按可理解的历史语境持续进入 production，不等待一个“最小版本”全部冻结；
- 隋唐长安继续作为默认精选场景之一，而不是首页唯一时间范围。

原始隋唐配额仍可作为该专题的内容完整度参考：24 人物、32 地点、48 事件、7 路线、100+ 关系，但不再叫 MVP 门禁。

## 3. 全历史时间结构

### 3.1 首页时代轨道

建议第一版时代入口：

1. 神话与传统起源；
2. 印度早期佛教与华夏文明原型；
3. 西周与先秦诸子；
4. 秦汉帝国与佛教入华；
5. 魏晋南北朝：玄学、道教制度与佛典翻译；
6. 隋唐：三教制度化与跨区域传播；
7. 五代、宋、辽、金：禅、理学与内丹；
8. 元代：跨地域宗教网络；
9. 明清：心学、民间信仰、经典整理与宗派延续；
10. 近现代与全球传播。

时代轨道不是互斥的教科书章节。人物、经典、路线和后世接受可以跨越多个时期。

### 3.2 三种时间

每个人物和关系允许同时拥有：

- `historicalTime`：生平、活动、事件、机构任职和旅行；
- `traditionalTime`：传统谱系、神话顺序、圣贤纪年或宗教叙事；
- `receptionTime`：后世祭祀、神格化、注疏、艺术表现、庙宇和文化记忆出现的时间。

历史时间使用 BCE/CE 连续轴；神话人物不强行获得伪 BCE 年份。神话与传统人物可以在“传统顺序”中出现，同时把最早文献见证和后世接受放在历史轴上。

### 3.3 首页时间交互

- 默认显示全历史密度与重要人物聚合；
- 点击时代后，地图、人物、事件、地点、路线和关系同步过滤；
- 时间轴 brush 可以选择任意历史区间；
- “历史时间 / 传统顺序 / 接受史”三种轨道共享当前人物和地图视口；
- 选择人物后，时间轴同时显示生平、传统叙事和后世影响，不把三者压成一个日期。

## 4. 人物的空间位置规则

“每个人物都能找到位置”不等于“每个人物都获得一个经纬度”。位置分为七类：

| 位置类型 | 进入现实地图 | 示例用途 |
|---|---|---|
| `exact_site` | 是 | 可核实寺院、遗址、建筑或事件地点 |
| `city_centroid` | 是 | 文献只支持城市尺度活动 |
| `approximate_region` | 是 | 只可定位地区或路线走廊 |
| `traditional_association` | 是，特殊样式 | 传统记载中的出生、会见、修行或显圣地点 |
| `memory_or_cult_site` | 是 | 后世庙宇、祭祀、艺术、纪念和地方记忆 |
| `route_corridor` | 是，线/走廊 | 求法、游学、传播、东渡、迁徙和朝圣 |
| `symbolic_cosmos` | 否，进入神圣画布 | 须弥山、天界、佛国、三清境等象征空间 |

每个人物—位置关系还必须标明空间角色：

```text
birth / activity / teaching / translation / institution /
journey / event / death / burial / memory / cult / representation /
traditional_episode / symbolic_abode
```

### 4.1 历史人物

- 地图默认显示其有证据的活动地点和路线；
- 争议地点使用虚线光晕和置信度；
- 后世纪念地不会被渲染成其本人到访；
- 点击人物后，地图显示“生平活动”和“后世接受”两组可切换节点。

### 4.2 神话人物与神祇

- 在神圣地理画布中显示象征位置、谱系和文本来源；
- 在现实地图中只显示有文献或物质证据的祭祀、庙宇、图像、地方传统和接受地点；
- 例如观音可以连接神圣的补陀洛迦，同时连接普陀山、敦煌、龙门等现实接受地点，但不宣称神圣人物以历史人物方式到访这些地点；
- 盘古、女娲、伏羲等进入传统顺序，并连接文献见证与后世祭祀地点，不给出伪历史出生地。

### 4.3 历史人物与神格化身份

历史人物和后世神圣身份采用两个节点，通过 `deified_as`、`identified_with`、`remembered_in` 连接：

```text
老子（传统圣贤/历史争议） → 太上老君（神圣身份）
张道陵（历史人物）       → 天师神圣谱系
释迦牟尼（历史/传统人物） → 佛陀神圣叙事层
```

不能把后世神格化内容全部写回历史人物生平。

```text
├──────────────────────────────────────────────────────────────────┤
│ 神话起源 | 先秦 | 秦汉 | 魏晋南北朝 | 隋唐 | 宋元 | 明清 | 现代 │
├──────────────────────────────────────┬───────────────────────────┤
│ 真实历史地图 / 神圣地理画布           │ 人物 | 事件 | 地点 | 路线 │

├──────────────────────────────────────┴───────────────────────────┤

└──────────────────────────────────────────────────────────────────┘
```

### 7.2 核心交互循环

```text
选时代或搜索人物
→ 地图定位其活动/传统/接受地点
→ 时间轴显示生平、事件与后世影响
→ 右侧切换相关人物、事件、地点、路线、经典
→ 点击节点打开统一详情抽屉
→ 进入展厅、原典或研究档案
→ 关闭后回到原地图场景
```

### 7.3 地图图层

- 地点；
- 城市与地区；
- 寺院、道观、文庙、书院、译经场和宫廷机构；
- 人物活动；
- 历史事件；
- 求法、传播、游学、东渡、朝圣和制度路线；
- 文化遗产与后世记忆；
- 传统关联地点；
- 神圣地理入口。

### 7.4 地图视觉语义

- 颜色表示传统或 convergence；
- glyph 表示地点/机构/事件类型；
- 实线、虚线和光晕表示证据与坐标置信度；
- marker 大小表示当前筛选下的关系密度，不直接表示人物“重要性”；
- 聚合点显示人物、事件和地点数量；
- 放大时从区域 → 城市 → 机构/遗址逐层展开；
- 不依赖 hover，触控和键盘都能完成主要操作。

## 9. 数据与静态读取调整

### 9.1 地图专用 read models

建议 compiler 生成：

```text
/maps/index/{locale}.json                     全局轻量索引
/maps/eras/{eraSlug}/{locale}.geojson         分时代地点/事件
/maps/regions/{regionSlug}/{locale}.geojson   分区域地点/事件
/maps/figures/{figureSlug}/{locale}.json      人物轨迹与位置层
/maps/routes/{routeSlug}/{locale}.geojson     路线/走廊
/maps/cities/{placeSlug}/{locale}.json        城市人物/事件/机构聚合
/maps/cosmos/{tradition}/{locale}.json        无经纬度神圣空间
```

### 9.2 浏览器加载纪律

- 首屏只加载全局轻量索引、当前时代地图包和列表摘要；
- 人物详情、城市展开、完整关系和来源按需加载；
- 全历史数据通过时代/区域拆包，不一次下载全部 dossier；
- 地图缩放决定加载区域和 marker 层级；
- 已加载数据缓存于当前会话，切换人物不重复请求。

### 9.3 每个人物的最低地图闭环

这不是 MVP 数量门槛，而是单个人物的数据完整性规则：

- 有人物类别：historical / traditional / sacred / mythic / compound；
- 有历史时间、传统时间或明确 `undated`；
- 至少一个 position record，或明确 `position_pending`；
- 每个位置有 spatialRole、positionKind、置信度和来源；
- 至少一个事件、文本、言论、制度或后世影响关系；
- 历史人物后世神格化时建立独立 sacred identity；
- 点击人物后地图、时间轴和右侧列表都有解释性结果。

## 11. production-only 简化发布流程

### 11.1 新原则

- Cloudflare production 是当前在线测试和复盘地址；
- 不再为普通内容和界面迭代创建独立 Preview alias；
- 不再要求每批 Alpha 内容走 Public RC promotion；
- 内容的 fact/rights/review 状态继续保留并在 Research 显示，但不阻止研究 Alpha 同步到 production；
- Cloudflare 不是长期平台依赖，站点继续保持纯静态、可迁移和 provider-neutral；
- 每个 production deployment 仍记录 unique URL、deployment ID、artifact/version 和 handoff，保证可回滚。

### 11.2 按风险分级验证

#### 内容与位置数据批次

```text
compiler build
→ schema/content/map verifier
→ Web build
→ production deploy
→ default + unique URL 核心 JSON/HTTP smoke
→ HANDOFF
```

#### 首页、地图和普通 UI 批次

```text
typecheck + unit tests
→ 地图/首页 targeted E2E + axe
→ Web build
→ production deploy
→ production browser smoke
→ HANDOFF
```

#### schema、compiler、路由或部署脚本批次

```text
full npm run check
→ full E2E
→ build
→ production deploy
→ 完整 HTTP/JSON/browser smoke
→ HANDOFF
```

这样取消重复环境和 promotion 仪式，但不取消与改动风险直接相关的验证。

### 11.3 部署批次纪律

- 一个批次只包含一个可描述的结果，例如“首页地图骨架”或“当前 12 人位置补齐”；
- 部署前记录 Git 状态和基线 commit/artifact checksum；
- 部署后只以 default production 地址为用户事实基准，unique URL 用于审计和回滚；
- 线上 smoke 失败立即恢复上一已知版本，不在坏 production 上继续叠改；
- HANDOFF 顶部只保留一个“当前”，旧部署明确标为历史；
- Public RC2 和旧 Preview 文档冻结为历史，不再随日常 production 迭代更新。

- 历史、传统、神话、神圣和后世神格化身份不混写；

- 神话/神圣人物可见象征位置和现实接受地点；
