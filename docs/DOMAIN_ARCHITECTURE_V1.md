# 道·儒·佛数字博物馆：立体知识架构 v1

状态：架构规划稿；Phase 0 的关系类型、限定条件、人物类别、言论归属、read model 传递和 Explore 共享语境聚焦已落地，跨时代 A 批次已进入 Preview，尚未进入 Public RC。此文档继续作为 schema、内容和 Explore 产品的共同边界。

## 1. 核心判断

本项目的基本单位不是“人物卡片”，而是一个可追溯的历史语境：

```text
谁（人物/群体）
在什么时间阶段
于什么地点、机构、路线或象征空间
参与了什么事件、文本、制度或言说
形成了什么关系
后来如何被记忆、解释、神格化或产生影响
每一项判断由什么来源支持，确定性如何
```

“人物—空间—时间”是最容易被访客理解的入口，但不是全部模型。人物、事件、地点、空间、关系、言论、历史地位和后世影响都应进入同一个可审计的关系网络。

## 2. 分层模型

### 2.1 身份层：谁/什么

身份层保存稳定实体，不直接承载所有叙述：

- `figure`：历史人物、传统圣者、神圣人物或神话人格；
- `event`：旅行、译经、制度建立、战争、政策、祭祀或记忆形成；
- `place`：现实地点、历史地点、区域锚点或神圣象征节点；
- `institution`：寺院、道观、官学、译场、宫廷机构和网络；
- `route`：求法、传播、翻译、学习或官方旅行的空间廊道；
- `text` / `text_version` / `passage`：作品、版本和可定位的言论/段落；
- `concept` / `tradition` / `museum_object`：思想、传统分类和物质证据。

身份层回答“它是谁”，不直接回答“某一年在哪里做了什么”。

### 2.2 事实层：发生了什么

关系不是装饰性连线，而是一条带限定条件的事实断言：

```text
主体 --关系类型--> 客体
       ├─ 时间范围/时间类型
       ├─ 空间角色或空间层
       ├─ 证据层、置信度、来源
       ├─ 版本、语言和权利条件
       └─ 审核与发布状态
```

建议优先补齐这些关系类型：

| 关系 | 用途 |
| --- | --- |
| `participated_in` | 人物参与事件，避免把人物生平和事件混成一段简介 |
| `occurred_at` | 事件发生于地点、机构或路线节点 |
| `active_in` / `travelled_through` | 人物的活动、经过或驻留空间 |
| `translated_or_transmitted` | 人物/机构与文本或版本的传播、翻译关系 |
| `commented_on` | 人物或文本与注释对象的关系 |
| `attributed_to` | 段落/言论与说话者或传统归属，明确归属状态 |
| `received_by` | 后世人物、机构、传统或文本如何接收前人/文本 |
| `remembered_in` | 某人物/事件在地点、机构或仪式中的记忆形成 |
| `deified_as` | 历史人物与后世神格化身份之间的区别性关系 |
| `influenced` | 只在有方向、时间和证据时使用，不作为泛化的“有关” |

不建议继续用 `related` 数组承载事实关系。它可以保留为编译后的展示缓存，但 source of truth 应是有来源、有时间和有审核状态的关系记录。

### 2.3 言论层：说了什么/谁这样说

`passage` 已经适合作为言论载体，但需要补“归属”维度：

- `direct_attestation`：有明确文本和版本定位的直接记录；
- `attributed_saying`：传统上归于某人物，但文本形成晚于人物；
- `recorded_by_others`：由弟子、史家或传记记录；
- `later_literary_voice`：后世文学或宗教叙事中的人物声音；
- `anonymous_or_composite`：无法安全归于单一说话者。

每条言论都应同时指向 `text` 和 `text_version`，并可通过 `attributed_to` 指向人物；不能只把引文放进人物简介的 `quote` 字段。`quote` 只作为展示字段，不能替代来源和归属关系。

### 2.4 历史状态层：怎样知道/怎样被叙述

“历史地位”不应压缩成一个主观等级。至少拆成四个维度：

1. **存在/历史性**：`documented`、`inferred`、`traditional`、`mythic`、`contested`；
2. **证据层**：历史文献、传统叙事、神话象征、后世神格化、文学再现、学术解释；
3. **文本归属**：作者、传述、编纂、匿名、复合或争议；
4. **后世状态**：经典化、制度化、祭祀化、神格化、再阐释或跨传统传播。

“重要性/知名度”可以作为策展排序，但必须标记为 curatorial metadata，不能被误读为历史事实。

### 2.5 后世影响层：怎样被接收和改变

后世影响最好拆成可见的“接收事件”或带时间的 `received_by` 关系：

```text
老子/《道德经》
  → 某一时期的注释者、制度、宗派或政治语境
  → 某一地点/机构
  → 产生新的文本、仪式、身份或神格化解释
```

这样可以区分：

- 人物本人做过的事情；
- 后人如何解释这个人物；
- 后世影响是否有直接证据，还是策展推断。

## 3. 时间与空间的统一规则

### 3.1 时间是多条断言，不是一个日期字段

同一人物可以有多条不同性质的时间：生平、活动、离开/返回、文本流通、制度记忆、崇奉出现、神格化和传统日期。早期人物进入隋唐展览时，应同时呈现：

- `origin_time`：人物或文本的历史/传统源头；
- `reception_time`：隋唐时期的翻译、注释、制度吸收或祭祀记忆；
- `later_reception_time`：更晚的神格化、经典化或现代再阐释。

不能为了让时间轴好看，把先秦或古印度人物伪装成隋唐同时代人物。

### 3.2 地点与空间不是同一个概念

- **地点**是可命名的实体，可能有坐标、区域范围或象征节点；
- **机构**是发生活动的制度空间；
- **路线**是多个地点和事件之间的廊道；
- **空间角色**描述人物/事件与地点的关系：出生、活动、经过、翻译、传播、记忆、祭祀或象征；
- **现实地图**只呈现有现实地理依据的地点；
- **神圣宇宙**呈现象征空间，不能伪造经纬度。

地图、时间轴和关系图必须由同一关系集合派生，不能各自维护一套人物地点名单。

## 4. 现有工程盘点

已经成立的部分：

- entity kind 已覆盖人物、事件、地点、机构、路线、文本、段落和对象；
- `TemporalAssertion` 已支持精确、范围、世纪、传统日期和无时间状态；
- `PlaceProfile` 已区分现实地点、区域锚点、传奇地点和神圣象征地点；
- `RelationRecord` 已有来源、置信度、证据层、审核状态、时间断言和结构化 qualifiers；Phase 0 已加入人物—事件、事件—地点、言论归属、后世接收/记忆/神格化关系类型；

## 5. 分阶段改造路线

### Phase 0：冻结架构边界（现在）

- 暂停批量新增人物；
- 扩充关系 registry 和关系 qualifiers（已完成第一版）；
- 为 passage 增加言论归属/来源状态（已完成字段和数据库迁移，具体人物归属待证据审核）；
- 保持现实地图与 sacred cosmos 的硬边界；
- 将 75 条双语关系 read model 以一致性门禁接入 Preview，并用玄奘、司马承祯、孔颖达、老子、孔子和释迦牟尼作为六个完整人物档案样本；
- 写一组“完整人物档案” golden fixtures，作为编译和发布测试样本。

### Phase 1：完成一个可审计的立体人物档案

以玄奘为样本，补齐：

- 人物身份与历史性；
- 玄奘参与的出发、求法、返回、译经等事件；
- 事件与长安、敦煌、洛阳、译场/寺院的关系；
- 代表性言论/文本的版本和归属状态；
- 隋唐时期的接受与制度化影响；
- 关系级时间、空间角色、来源和审核记录。

然后用司马承祯和孔颖达复用同一模型；这一批六个 dossier 已通过结构门禁。Public RC 仍可只发布前三位完成审核的档案，不必等待 89 个内容实体全部完成。

### Phase 2：增加跨时代入口人物（A 批次 Preview 已完成）

老子、孔子、释迦牟尼的 A 批次已进入 Preview：每人都有“源头时间 + 进入当前展览的接受时间”，并分别连接文本、地点、机构和后世传统；下一步是完成 edition/item/precise locator、rights 和 review 后，再决定是否进入 Public RC。候选名单和神话人物边界见：[人物选择与证据分层计划](FIGURE_SELECTION_AND_EVIDENCE_PLAN.md)。

### Phase 3：神圣/神话宇宙

观音、太上老君、伏羲、女娲、盘古等进入独立的 sacred cosmos / mythic exhibition；不混入历史人物数量，也不使用伪造历史年份或现实坐标。

## 6. 新内容的准入门槛

重点人物必须至少具备：

- 一条身份/历史性说明；
- 一条有来源的时间断言；
- 一条有来源的地点、机构或路线关系；
- 一条参与事件或文本/言论关系；
- 若声称“后世影响”，必须有带时间和对象的接收/影响关系；
- 每条关键关系都能回到 edition、item 或 precise locator；
- 双语、事实、传统、权利、编辑和 schema 审核记录。

重点事件必须至少具备：时间、参与者、发生地点/空间、事件类型、来源和不确定性说明。

## 7. 近期产品形态

Explore 不再只是四个并列按钮，而应围绕一个共享的 `context focus`：

```text
选择人物 → 同步显示事件、地点、时间段、文本/言论和后世影响
选择地点 → 同步显示在此活动、经过、传播或被记忆的人物与事件
选择时间 → 同步过滤人物、事件、空间和文本流通
选择言论 → 回到说话者、版本、事件、地点和后世解释
```

地图缩放/拖动是交互基础；真正的核心完成标准是地图节点、时间条目、关系边和实体详情可以互相聚焦，并且所有结果来自同一 source of truth。
